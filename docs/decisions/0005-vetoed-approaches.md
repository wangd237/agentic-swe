# ADR-0005: 设计哲学调研中否决的方案

**日期**: 2026-08-30
**状态**: 已采纳（否决清单）

**来源**: 2026-08-30 对 pi / deepseek-harness / claude code 三个开源 harness 的设计哲学调研。

## 否决清单

| 方案 | 来源 | 否决理由 |
|---|---|---|
| 全量事件总线/插件系统 | pi 扩展机制 | 项目已收敛，重构 2527 行主循环的风险远大于收益；18 处干预点远少于事件总线的复杂度阈值。P1-1 的轻量 wrapper 在需要时足够。 |
| 恢复 MySQL/ES/Redis 架构 | 旧版记忆 | 当前规模纯文件持久化是正确选择。引入数据库增加运维负担、启动延迟，且当前无持久化查询需求。 |
| 子代理/进程隔离 | pi / claude code | 主上下文阶段状态传递成本高；当前 run 生命周期短（16 轮上限），隔离收益存疑。 |
| 持久化状态机（effect sandwich） | pi harness 规范 | 面向长生命周期可恢复 run；本项目 run 短，状态恢复需求低。 |
| 原语/政策分离式重构 | dsh 哲学 | 定位阶段与门禁紧耦合是有意设计——verification strength / generation 的交叉校验是 resolved 判定的正确性来源，剥离会破坏正确性。 |

## 决策依据

这些否决不是"没时间做"，而是"做了反而有害"。每个被否决的方案在来源项目中都有其合理性，但移植到本项目会与以下约束冲突：

1. **run 生命周期短**（max_iterations=16），不需要可恢复/持久化状态机
2. **阶段门禁与证据校验耦合**（verification strength × generation）是正确性基础
3. **项目已收敛**，大规模重构的回归风险不可接受
4. **当前架构复杂度**已匹配问题规模（SWE-bench Lite 级别），过度工程化无益
